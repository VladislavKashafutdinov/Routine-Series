# Как должно быть

Планируемая, но ещё не реализованная функциональность.

Целевая схема вложенности компонентов вынесена в [TARGET_SCHEMA.md](TARGET_SCHEMA.md).

## Различные пояснения

**Начисленная награда** == выданная награда.

### SeriesDefinition

Время от времени пользователю требуется изменить параметры, по которым будут формироваться серии и начисляться награда. Но при этом все серии, которые сформированы из `completion`, выполненные до изменения параметров, должны остаться неизменными. Поэтому вводится сущность `SeriesDefinition` - это запись о новой версии параметров формирования серий, которые должны применяться при формировании серий, состоящим из `completion`, выполненных после даты создания новой `SeriesDefinition`.

### RewardCounters

Компонент, показывающий состояние наград по активности с разбивкой по валютам:

- **Заработано** (`earnedByCurrency`) — сумма наград за все завершённые серии в данной валюте
- **Начислено** (`issuedByCurrency`) — сумма уже выданных наград в данной валюте
- **К начислению** (`unissuedByCurrency`) — заработано минус начислено

Если для валюты нет ни заработанных, ни начисленных наград — валюта не показывается.
Если неначисленная награда > 0 — отображается кнопка/предложение «Начислить».

Предлагает сделать начисление награды, если unissuedByCurrency > 0 (создаётся запись в `RewardIssue`)

## Функциональность

### Общая
- Перемотка времени (тестовый режим): кнопки вперёд/назад, виртуальная дата, сброс на сегодня
	- Виртуальное сегодня — дата, установленная пользователем через перемотку времени. Если перемотка не активна, виртуальное сегодня совпадает с реальным.
- Локализация русский/английский, автоопределение языка браузера
- Экспорт и импорт всех данных в json

	- Активность, помеченная как архивная не должна отображаться
	- Для невыполненной активности: кнопка отметки выполнения активности в текущую дату (в том числе при использовании виртуального сегодня, см. "Перемотка времени"). Если активность отмечена как выполненная сегодня (создана запись в `Completion`), то активность попадает в раздел для выполненных
	- Для выполненной активности: кнопка отмены отметки выполнения в в текущую дату (в том числе при использовании виртуального сегодня, см. "Перемотка времени") - удаляется запись в `Completion` и активность попадает в раздел невыполненных

#### Виджет серии 
- Показывает дату старта и конца
- Визуальное отображение в виде последовательных квадратиков
	- Квадратики отличаются друг от друга в зависимости, была ли выполнена активность в день, которому соответствует квадратик
- На вход принимаются
	- дата начала серии
	- количество дней из параметров в `SeriesDefinition`
	- список `completion`, входящих в серию
- Виджет должен самостоятельно рассчитывать состояние серии. 

#### Как формируются серии
Серии вычисляются на основании записей в completion и seriesdefinition: 
В алгоритме используются только те completion и seriesDefinition, дата которых <= virtualToday

##### Старая версия алгоритма
0. seriesdefinition сортируются в связанный список по дате создания
1. для каждой seriesdefinition делается выборка множества completion, у которых 
	- если это первая `SeriesDefinition` в списке: попадают все completion с датой < даты создания следующей seriesdefinition (включая те, что до даты создания первой)
	- если это последняя `SeriesDefinition` в списке, то условие попадания completion в выборку: date >= даты создания seriesdefinition
	- иначе, условие попадания completion в выборку: date >= даты создания seriesdefinition, но < даты создания следующей в списке seriesdefinition. 
	
	эти выборки completion по каждой seriesdefinition называются seriesDefinitionCompletions
2. после этого в каждой seriesDefinitionCompletions надо отсортировать completion по date
3. после этого надо раздробить seriesDefinitionCompletions на серии completion. 
	- N = seriesLength из того SeriesDefinition, с которым связана данная группа completion
	- Серия считается **выполненной**, если количество completion серии равно N
	- Серия считается **активной**, если ее размер меньше N И date у последнего completion - это вчера или сегодня (относительно "виртуального сегодня", см. "Перемотка времени")
	- Серия считается **прерванной**, если серия не активна И количество completion серии меньше N
	- Серия считается **текущей**, если виртуальное сегодня находит между началом и концом серии. "Текущая" - это не статус серии, а термин, необходимый чтобы определить, какая серия сейчас находится в прогрессе.
	- Алгоритм дробления: 
	- создать связанный список series. каждый элемент списка series - это список из completion
	- цикл по всем completion внутри seriesDefinitionCompletions
		- если это первый шаг - в series попадает новая серия
		- если это не первый шаг И (date of completion - date of предыдущего completion) > 1 суток (условие прерывания серии) - в series попадает новая серия (условие прерывания серии должно быть обернуто в отдельную функцию)
		- если размер последней серии равно N, то в series попадает новая серия
		- добавить completion в последнюю серию из series

##### Версия алгоритма 2

0. Определить 
	- firstSeriesDefinition: самая минимальная seriesDefinition по creationDate
	- lastSeriesDefinition: самая максимальная seriesDefinition по creationDate
	- virtualYesterday: virtualToday минус 1 день
1. Отсортировать список всех completion по дате выполнения. Получаем sortedCompletions.
2. Разбить sortedCompletions по разрывам дат. Получаем список списков completion - superSeriesList. Каждый элемент внутри superSeriesList должен быть списком completion, отсортированным по completion.date
3. Цикл: для каждой superSeries из superSeriesList: разбиение superSeries на серии и формирование результирующего списка из computedSeries: 
	0. Завести переменную processingSeries - пустой список completion 
	1. Цикл для каждого completion с индексом completionIndex внутри superSeries 
		0. определить completionSeriesDefinition: ассоциация completion с seriesDefinition по следующему условию: 
			- ЕСЛИ completion.date < firstSeriesDefinition.creationDate: firstSeriesDefinition
			- ИНАЧЕ: seriesDefinition минимальная по seriesDefinition.creationDate среди всех seriesDefinition, у которой seriesDefinition.creationDate <= completion.date
		1. добавить completion в processingSeries
		2. ЕСЛИ processingSeries.length == completionSeriesDefinition.seriesLength (признак завершенной серии):
			1. добавить в результирующий список серий новую серию (computedSeries):
				- с набором completion из processingSeries
				- параметрами из completionSeriesDefinition
				- статус серии: завершенная 
			2. обнулить processingSeries (начинаем набор новой серии)
		2. ИНАЧЕ ЕСЛИ completionIndex == (superSeries.length - 1) (это последний день в супер-серии)
			1. ЕСЛИ completion.date >= virtualYesterday (признак активной серии):
				1. добавить в результирующий список серий новую серию (computedSeries):
					- с набором completion из processingSeries
					- параметрами из lastSeriesDefinition
					- статус серии: активная
				2. обнулить processingSeries (начинаем набор новой серии)
			2. ИНАЧЕ (это последний день супер-серии в прошлом, супер-серия в прошлом заканчивается либо завершенной серией, либо прерванной):
				1. добавить в результирующий список серий новую серию (computedSeries):
					- с набором completion из processingSeries
					- параметрами из completionSeriesDefinition
					- статус серии: прерванная
				2. обнулить processingSeries (начинаем набор новой серии)

##### Триггеры пересчета серий
Серии должны пересчитываться, если:
- было добавлено completion
- было удалено completion
- был добавлен seriesDefinition
- произошла смена даты сегодня (по часам, либо при перемотке времени)

#### Как считается награда по активности в каждой валюте:
Для каждой серии существует своя `seriesDefinition` из истории версионирования `seriesDefinition` (см. "Как формируются серии"). Таким образом каждой серии соответствует своя валюта и сумма награды.

**Общая начисленная награда** == сумма всех начисленных наград, связанных с активностью.
Для каждой валюты Общая начисленная награда считается отдельно.

**Награда за завершенную серию** == награда в `seriesDefinition`, с которой связана серия (см. "Как формируются серии")

**Заработанная награда** == сумма наград за завершенные серии, у которых `seriesDefinition` имеют общую валюту.
Для каждой валюты Заработанная награда считается отдельно.

**Неначисленная награда** == заработанная награда минус общая начисленная награда
Для каждой валюты Неначисленная награда считается отдельно.
