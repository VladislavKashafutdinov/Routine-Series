## План разработки UI

### Фаза 1: Главная страница — Активности сегодня

**Цель:** пользователь добавляет активность, видит разделение на выполненные/невыполненные, отмечает/отменяет выполнение на сегодня.

**Зависит от:** SeriesDefinition, Activity.archived.

**Страница:** «Выполнение» (Dashboard).

**Компоненты:**
- `Dashboard` — заголовок страницы, форма добавления, две секции
- `AddActivity` — форма: название, длина серии, награда, валюта (встроена в Dashboard)
- `Section` — заголовок «Не выполнено» / «Выполнено» + список карточек
- `ActivityCard` — виджет активности на главной странице:
  - Редактируемое название
  - `SeriesProgress` — ряд квадратиков активной серии (только отображение: зелёные/серые, без кликов)
  - Кнопка «Отметить» (для невыполненных) / «Отменить» (для выполненных)
  - Кнопка удаления (с подтверждением, soft-delete при наличии Completion/RewardIssue)
- `PageTabs` — переключение: «Выполнение» | «Мониторинг» | «Архив» (в шапке)

### Фаза 2: Перемотка времени

**Цель:** перемотка виртуальной даты вперёд/назад, пересчёт состояния на любой день.

**Зависит от:** ничего.

**Компоненты:**
- `TimeOffsetContext` — хранит смещение в днях, доступно всему дереву
- `TimeTravel` — ◀ дата ▶ «Сегодня» в шапке
- Все вызовы `today()` и `getDateRange()` учитывают offset

### Фаза 3: Виджет серии (интерактивный)

**Цель:** полноценный виджет серии с кликабельными квадратиками для страницы мониторинга.

**Зависит от:** Вычисление серий (алгоритм из README).

**Компоненты:**
- `SeriesWidget` — ряд из N квадратиков (N = seriesLength) с обработчиками клика:
  - Клик на первый серый → отметить выполнение в этот день
  - Клик на последний зелёный → отменить выполнение в этот день
  - Будущие даты не кликабельны
  - Показывает даты старта и конца серии
  - Используется на странице мониторинга (вкладка «История серий»)
- `SeriesProgress` (из Фазы 1) остаётся без изменений — только отображение, без интерактивности

### Фаза 4: Страница мониторинга

**Цель:** отдельная страница с полной историей серий и наград по каждой активности.

**Зависит от:** RewardIssue, Вычисление серий, Фаза 3 (SeriesWidget).

**Страница:** «Мониторинг» (MonitoringPage).

**Компоненты:**
- `MonitoringPage` — список раскрывающихся блоков
- `ActivityAccordion` — блок активности:
  - Заголовок: название + счётчики начисленной / неначисленной награды
  - Кнопка «Начислить» (если неначисленная > 0) → создаёт `RewardIssue`
  - Кнопка «Редактировать параметры» → `EditSeriesDefinition`
  - Вкладка «История серий» — список `SeriesWidget` (по одному на каждую серию), пагинация
  - Вкладка «История начислений» — таблица `RewardIssue`:
    - Колонки: дата, сумма, валюта, действия
    - Inline-редактирование (дата/сумма/валюта)
    - Удаление записи (с подтверждением)
    - Пагинация

### Фаза 5: Архив + Экспорт/Импорт

**Цель:** управление архивными активностями, сохранение/восстановление всех данных.

**Зависит от:** Activity.archived.

**Страница:** «Архив» (ArchivePage).

**Компоненты:**
- `ArchivePage` — список архивных активностей, кнопка «Восстановить» у каждой
- Кнопка «Экспорт» — собирает все таблицы БД в JSON, скачивает файл
- Кнопка «Импорт» — выбор JSON-файла, валидация, замена данных (с подтверждением)

### Фаза 6: Редактирование SeriesDefinition

**Цель:** изменение параметров активности с сохранением истории версий.

**Зависит от:** SeriesDefinition, Фаза 4 (страница мониторинга).

**Компоненты:**
- `EditSeriesDefinition` — форма в блоке активности:
  - Предзаполнена текущими значениями из последнего `SeriesDefinition`
  - При сохранении создаётся новый `SeriesDefinition`, старый не меняется
  - Все вычисления серий и наград автоматически пересчитываются
